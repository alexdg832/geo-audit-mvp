# GEO Research: What Determines Whether AI Engines Mention and Cite a Business

Research date: 2026-09-29. Synthesis of 280 verified claims from 14 research batches (studies, ChatGPT, Perplexity, Google, Claude, source trust, technical, tools, local, nondeterminism, and four API batches).

## 0. How to read this document

Purpose. This document is the evidence base for the customer-facing methodology of a paid GEO audit that scores small and mid-size businesses 0-100 across six pillars (AI Visibility, Source Authority, Entity Clarity, Content Answerability, Technical AI Readiness, Competitive Position). It separates what engines state, what studies measured, and what is only practitioner opinion.

Strength labels on each finding:

- Proven: the statement appears in official engine or API documentation, an engine's own published terms, or a peer-reviewed paper, and was confirmed verbatim on the page. "Proven" means the source says it; it does not mean the effect is causal or that it transfers to a given business.
- Suggestive: a vendor or industry study with a stated method (sample, period, statistic), an arXiv preprint, or a news report of a first-party statement. Findings are correlational unless the bullet says otherwise.
- Speculative: expert opinion, practitioner surveys, vendor marketing without a stated method, or single-account observations.

Source types: official engine doc; peer-reviewed study; industry study with method; vendor marketing; news; expert opinion. Product documentation of GEO tools (pricing pages, help centers) is filed as vendor marketing because it is not an AI engine's documentation.

Verification status. Every claim was fetched and read by the research step and checked by a verification step; only fetched pages are cited. A claim marked "(partially verified: ...)" had a number, wording, or scope corrected against the page; the note says what changed. Of the 280 claims supplied, 229 carry verdict verified and 51 carry verdict partially verified; none was unsupported or unreachable. The appendix "Excluded claims" therefore lists zero excluded claims, followed by figures the researchers saw circulating but could not confirm on any fetched page.

Counting rule. Where two or more batches verified the same page and the same statement (for example Google's AI-features page or OpenAI's crawler page), the bullets are merged and the merge is noted; nothing was dropped.

Dates. Publication or last-updated dates are given as shown on the page; "undated" means the page shows none. Sources from 2024 or earlier are flagged "older".

Numbers. Every number carries the URL of the page it was read from. Where the source hedges ("roughly", "about", "~"), the hedge is kept. No number was rounded or derived here except where explicitly marked as arithmetic.

Criteria labels used in Section 9:

- evidence-backed: the criterion rests on an engine's own documentation or terms, or on a peer-reviewed result; "(lab-conditional)" means the peer-reviewed result holds only once a page is already in the model's context.
- heuristic: the criterion rests on correlational vendor data, preprints, expert opinion, or inference; it may be scored but must be labeled as such to the customer.

## 1. What measurably influences whether an LLM mentions or cites a business

### 1.1 Getting retrieved and placed well in context beats on-page rewriting

- [Proven, older] In the original GEO paper (Aggarwal et al., KDD '24; arXiv 2311.09735, v1 Nov 2023, v3 28 Jun 2024), the authors state that their top-performing methods, Cite Sources, Quotation Addition and Statistics Addition, "achieved a relative improvement of 30-40% on the Position-Adjusted Word Count metric". Table 1 values: No Optimization 19.5, Cite Sources 24.9, Statistics Addition 25.9, Quotation Addition 27.8. The setup fetched the top 5 Google sources per query and generated answers with gpt-3.5-turbo, so the optimized source was already in the model's context. This is a 2023/2024 lab result, not a live-engine measurement. Source: [ar5iv.labs.arxiv.org/html/2311.09735](https://ar5iv.labs.arxiv.org/html/2311.09735) (peer-reviewed, KDD 2024; submitted 16 Nov 2023, revised 28 Jun 2024). (partially verified: Page reachable. The quoted sentence is a truncation: the paper's actual sentence reads 'our top-performing methods, Cite Sources, Quotation Addition, and Statistics Addition, achieved a relative improvement of 30-40%...'. The claim drops Cite Sources from the 30-40% group and treats it as merely 'also improved'; the paper groups all three. (Arithmetic from Table 1: Cite Sources 24.9/19.5 is a 27.7% gain, Statistics 32.8%, Quotation 42.6% — the '30-40%' is the paper's own framing.) All table numbers, gpt-3.5-turbo, KDD 2024 and the in-context setup are confirmed.)
- [Proven, older] The same paper (GEO-bench of 10,000 queries) found that on the authors' GPT-3.5-turbo-based generative engine the top methods "Cite Sources, Quotation Addition, and Statistics Addition, achieved a relative improvement of 30-40%" on Position-Adjusted Word Count (15-30% on Subjective Impression), fluency and readability edits gave a 15-30% boost, keyword stuffing "offer[s] little to no improvement," and an authoritative tone showed "no significant improvement." In a separate test on Perplexity.ai, gains were smaller: Quotation Addition gave a 22% improvement on Position-Adjusted Word Count and Statistics Addition up to 9% and 37% on the two metrics. Source: [arxiv.org/html/2311.09735](https://arxiv.org/html/2311.09735) (peer-reviewed, KDD 2024). (partially verified: Page reachable and all quoted results appear, but the claim misattributes the 30-40% result to Perplexity.ai. Per the paper, the headline 30-40% figure was measured on the GPT-3.5-turbo-based engine; the Perplexity.ai evaluation (Section 6) reported 22% for Quotation Addition and up to 9%/37% for Statistics Addition.)
- [Proven, older] The GEO paper (arXiv 2311.09735v3, 28 Jun 2024) states of keyword stuffing: "While widely used for Search Engine Optimization, we find such methods offer little to no improvement on generative engine's responses." In Table 1, Keyword Stuffing scored 17.8 on Position-Adjusted Word Count versus 19.5 for No Optimization, i.e., below the unoptimized baseline in that lab setup. Source: [arxiv.org/html/2311.09735](https://arxiv.org/html/2311.09735) (peer-reviewed, KDD 2024).
- [Proven] C-SEO Bench (arXiv 2506.11097; abstract states "Accepted at NeurIPS Datasets & Benchmarks 2025") covers two search tasks (product recommendation, question answering) with three domains each (six total: Retail, Video Games, Books; Web, News, Debate) and "more than 1.9k queries and 16k documents" (Table 2: 1,185 + 736 queries; 11,605 + 4,755 documents). It finds "most current C-SEO methods are not only largely ineffective but also frequently have a negative impact on document ranking", that "traditional SEO strategies, those aiming to improve the ranking of the source in the LLM context, are significantly more effective", and that "as we increase the number of C-SEO adopters, the overall gains decrease, depicting a congested and zero-sum nature of the problem". Source: [arxiv.org/abs/2506.11097](https://arxiv.org/abs/2506.11097) (peer-reviewed, NeurIPS 2025 Datasets & Benchmarks; submitted 6 Jun 2025, v3 20 Oct 2025).
- [Suggestive] A critical survey posted to arXiv on 15 July 2026 (2607.14035v1) "reviews 45 studies selected under a November 2023–July 2026 publication window". Its abstract states the foundational GEO paper's "widely cited gains are valid within its experimental setting but conditional on a source already being present in a fixed context; they establish neither organic discoverability nor durable traffic effects", that "topical relevance and context position are the most reproducible levers", that "Generic heuristics generalize poorly" (Section 7.3), and that "No reviewed technique shows a stable, longitudinal, cross-platform causal effect on organic discoverability or downstream behavior." Summarizing C-SEO Bench, it reports "Only three of 54 method–domain combinations are significantly positive in the main experiment; none is positive in question answering." Source: [arxiv.org/html/2607.14035v1](https://arxiv.org/html/2607.14035v1) (preprint, expert review; 15 Jul 2026; not peer-reviewed; the 3-of-54 figure is the survey's summary of C-SEO Bench).
- [Suggestive] CITECHOICE (arXiv preprint 2609.15164, submitted September 14, 2026, not peer reviewed), a causal audit of 113 same-call document pairs from 129 agentic-search transcripts, found that "structured rendering concentrates citation credit rather than clearly increasing source admission. It raises target citation count by +0.50 citations per answer (95 percent CI [+0.20, +0.84]; Holm-adjusted p=.033)"; the effect on whether the target is cited at all was +4.5 percentage points and inconclusive (95 percent CI [-1.4, +10.4]; p=.168). Source: [arxiv.org/abs/2609.15164](https://arxiv.org/abs/2609.15164) (preprint with described method; 14 Sep 2026).
- [Suggestive] An observational measurement study (arXiv 2604.25707v2, 29 Apr 2026) of 602 prompts across ChatGPT, Google AI Overview/Gemini and Perplexity collected 21,143 valid search-layer citations, fetched 18,151 pages, and extracted 72 features. It reports "Contains numbers/statistics: +61.55%" relative influence uplift, and "Q&A pages show mean influence 0.0947 versus 0.1005 for non-Q&A pages, a -5.74% relative difference". The authors state "The influence score is a constructed observational proxy rather than a direct measure of hidden model attention" and avoid "causal claims that cannot be supported by the current static snapshot." Source: [arxiv.org/html/2604.25707v2](https://arxiv.org/html/2604.25707v2) (preprint; v1 28 Apr 2026, v2 29 Apr 2026).

Methodology consequence: content-method criteria (statistics, quotations, cited sources, structure) can be labeled at most "evidence-backed (lab-conditional)"; they do not get a page retrieved. Keyword density is not a positive criterion. Pillars that govern retrieval (Source Authority, Entity Clarity, Technical AI Readiness) should outweigh rewrite-style criteria.

### 1.2 Off-site signals: mentions, links, reviews, earned media

- [Suggestive] In a study published 26 May 2025, Ahrefs analyzed 75,000 brands (domains filtered for DR > 40, using each domain's highest-volume keyword with at least 800 monthly searches) using the Spearman correlation coefficient and reported "Web mentions (0.664) correlate much more strongly than backlinks (0.218)" with brand visibility in Google AI Overviews; "Roughly 26% had zero mentions". Ahrefs states "correlation ≠ causation". Vendor-published study with stated method. Source: [ahrefs.com/blog/ai-overview-brand-correlation](https://ahrefs.com/blog/ai-overview-brand-correlation/) (industry study with method; May 26, 2025).
- [Suggestive] Ahrefs' follow-up study (published 12 Dec 2025) of 75,000 brands, using the Spearman correlation coefficient, across ChatGPT, Google AI Mode and Google AI Overviews reports that "YouTube mentions show the strongest correlation with AI visibility (~0.737), outperforming every other factor across ChatGPT, AI Mode, and AI Overviews" (per engine: ChatGPT ~0.737, AI Mode ~0.740, AI Overviews ~0.712); branded web mentions 0.664/0.709/0.656; branded search volume 0.352/0.466/0.392; Domain Rating 0.266/0.285/0.326; content volume (~0.194) shows "almost no relationship"; and "ChatGPT shows the weakest correlations of all three AI assistants for almost every traditional brand authority signal". These are correlations, not causal effects. Source: [ahrefs.com/blog/ai-brand-visibility-correlations](https://ahrefs.com/blog/ai-brand-visibility-correlations/) (industry study with method; December 12, 2025). Verified independently in the studies and source-trust batches; merged here.
- [Suggestive] SE Ranking's study (published 24 Nov 2025) analyzed 129,000 unique domains and 216,524 pages across 20 niches, drawn from a dataset of 100,000 prompts, using an XGBoost regression model with SHAP analysis. Its ranked-factor chart puts "the number of referring domains" at the top; the page states "Sites with over 32K referring domains are 3.5x more likely to be cited by ChatGPT than those with up to 200 referring domains" and that "high-trust domains (DT > 90) earn almost 4x more citations than low-trust sites (DT < 43)" (DT = SE Ranking's proprietary Domain Trust metric). The outcome variable (ChatGPT citations) differs from Ahrefs' AI Overview brand-mention variable, so the two studies are not directly comparable. Source: [seranking.com/blog/how-to-optimize-for-chatgpt](https://seranking.com/blog/how-to-optimize-for-chatgpt/) (industry study with method; November 24, 2025).
- [Suggestive] In the same SE Ranking study (24 Nov 2025; 129,000 domains, 216,524 pages, 20 niches), "Domains featured on multiple review platforms earn 4.6–6.3 citations, versus 1.8 for those absent from such platforms"; "Minimal Quora presence (up to 33 mentions) → 1.7 citations. Heavy Quora presence (6.6M mentions) → 7.0 citations"; and "The same applies to Reddit: from 1.8 to 7 citations across the scale." These are average ChatGPT citation counts by mention bucket, not causal estimates. The Reddit/Quora thresholds (millions of mentions) are far beyond SMB scale. Source: [seranking.com/blog/how-to-optimize-for-chatgpt](https://seranking.com/blog/how-to-optimize-for-chatgpt/) (industry study with method; November 24, 2025).
- [Suggestive] Chen et al. (Mahe Chen, Xiaoxuan Wang, Kaiwen Chen, Nick Koudas, University of Toronto; arXiv 2509.08919v1, 10 Sep 2025) "generated 1,000 consumer ranking prompts (10 categories × 100 each)", ran the study "in two regions (U.S., Canada) and focused analysis on three verticals" (consumer electronics, automotive, software), with additional multilingual (5 languages) and paraphrase-sensitivity tests. For US automotive: "Google leaned 39.5 percent Brand, 15.4 percent Social, and 45.1 percent Earned, while AI search delivered 81.9 percent Earned and 18.1 percent Brand." Source: [arxiv.org/html/2509.08919v1](https://arxiv.org/html/2509.08919v1) (preprint with described method; September 10, 2025).

Contradiction to carry into the methodology: Ahrefs (Spearman, outcome = brand mentions in AI Overviews) puts backlinks at 0.218 versus 0.664 for unlinked web mentions ([ahrefs.com](https://ahrefs.com/blog/ai-overview-brand-correlation/)), while SE Ranking (XGBoost/SHAP, outcome = domain citations in ChatGPT) calls referring domains the strongest predictor and reports a 3.5x citation likelihood gap ([seranking.com](https://seranking.com/blog/how-to-optimize-for-chatgpt/)). Different engines, outcomes and statistics; both correlational; neither causal. "Brand mentions > backlinks" is suggestive, not proven; both mention and link criteria are heuristic.

### 1.3 On-page characteristics associated with being cited (correlational)

- [Suggestive] "AI Answer Engine Citation Behavior: An Empirical Analysis of the GEO16 Framework" (arXiv 2509.10762, submitted 13 Sep 2025) used 70 product-intent prompts, collected 1,702 citations across Brave Summary, Google AI Overviews and Perplexity, and audited 1,100 unique URLs; "pillars related to Metadata and Freshness, Semantic HTML, and Structured Data showed the strongest associations with citation", and "Logistic models with domain clustered standard errors indicate that overall page quality is a strong predictor of citation". ChatGPT was not among the engines tested; associational, preprint, small prompt set. Source: [arxiv.org/abs/2509.10762](https://arxiv.org/abs/2509.10762) (preprint with described method; September 13, 2025).
- [Suggestive] Ahrefs (Louise Linehan, April 15, 2026) analyzed what it describes as "1.4 million ChatGPT 5.2 prompts from February 2025 (desktop)" and found that "search results with natural language URL slugs had an 89.78% citation rate, compared to 81.11% for those without." It also reports cosine similarity between the user prompt and page titles of 0.602 for cited URLs vs 0.484 for non-cited URLs (and 0.656 for the best-matching fan-out query vs cited title); that for cited pages "the median is around 500 days (~1.3 years old)"; and that "within a given retrieval set, freshness alone isn't enough. Relevance still does the heavy lifting". The "citation rate" denominator is results in ChatGPT's retrieval set, not all web pages. The page's dataset sentence ("February 2025" alongside "ChatGPT 5.2") looks like a typo on the source and is reproduced as written. Source: [ahrefs.com/blog/why-chatgpt-cites-pages](https://ahrefs.com/blog/why-chatgpt-cites-pages/) (industry study with method; April 15, 2026). Verified in the ChatGPT, technical and source-trust batches; merged here.
- [Suggestive] Ahrefs' October 28, 2025 analysis of the top 1,000 pages ChatGPT cited in September 2025 (Brand Radar) classified them as Wikipedia 29.7%, homepage/landing pages 23.8%, educational 19.4%, app store 6.6%, reviews 5.8%, news/media 5.2%, blog/article 1.9%; 28.3% (283 pages) had zero organic keywords, and 89.7% had been updated in 2025. Source: [ahrefs.com/blog/chatgpts-most-cited-pages](https://ahrefs.com/blog/chatgpts-most-cited-pages/) (industry study with method; October 28, 2025; top-1,000-page sample, author-classified).
- [Suggestive] Seer Interactive's July 24, 2026 study of 7,683 cited pages with readable dates (47,097 citations across ChatGPT, Gemini and Perplexity, March-June 2026) found 75% of cited pages were updated in the last year (Gemini 78%, ChatGPT 73%, Perplexity 65%); "By last update, 72% look fresh. But if that page was published in the last year, that citation rate drop to 42%." The authors conclude the freshness signal comes from updates rather than new publishing. Source: [seerinteractive.com](https://www.seerinteractive.com/insights/study-content-recencys-impact-on-ai-visibility-in-2026) (agency study with stated sample and period; July 24, 2026; "pages with readable dates" is a filtering caveat).

### 1.4 Being cited and being mentioned are different outcomes

- [Suggestive] Semrush, with Growth Memo (Kevin Indig), published on 9 Jun 2026 a study of 115 prompts, 3,981 domain appearances and 14 countries across ChatGPT, Google AI Overviews, Gemini and Google AI Mode, reporting "62% of AI citations are ghost citations. Your site gets a source link, but the AI never says your name in the answer" (61.7% in the methodology). It states "Short, conversational queries have brand mention rates of nearly 100%, while long, structured prompts have mention rates of just 2%-3%." Source: [semrush.com/blog/the-ghost-citations-study](https://www.semrush.com/blog/the-ghost-citations-study/) (industry study with method; June 9, 2026; 115 prompts is a small sample).
- [Suggestive] Growth Memo (20 Jul 2026), using Semrush AI Visibility Toolkit data covering 1,094 US ChatGPT categories from January through June 2026 (600,000+ citations, 220,000+ domains, 50,000+ brands), reports "the most cited domain was rarely (20.8%) the most mentioned. But the most mentioned brand was often cited (69.9%) at least once." An embedded AI Mode user study reports "74% of participants chose the item ranked first in the AI's response as their top pick" and "64% of AI Mode participants clicked nothing at all". Source: [growth-memo.com/p/does-topical-authority-matter-in](https://www.growth-memo.com/p/does-topical-authority-matter-in) (newsletter analysis of vendor data; July 20, 2026; user-study sample size not stated).
- See also Orbit Media's Claude figures (brands mentioned in 70% of answers, cited in 40%) in Section 2.4 ([orbitmedia.com](https://www.orbitmedia.com/blog/ai-citation-sources/)).

Methodology consequence: record "mentioned" and "cited" as separate outcomes per engine; keep audit prompts short and conversational; score mention share (and first-position mention) as the primary competitive outcome.

### 1.5 Engines draw from largely disjoint source pools

- [Suggestive] Growth Memo's "The Consensus Gap" (11 May 2026) analyzed 3.7 million URL citations across ChatGPT, Perplexity and Google AI Overviews from a random sample of 20,000 prompts (plus additional 5,000-prompt cohorts), Q3 2025 through Q1 2026, with a Europe-heavy, Spain-overrepresented geography, and found "91% of citations appeared in only one engine" (91.07%) while "only 2.37% of cited URLs show up across all 3 engines". Source: [growth-memo.com/p/the-consensus-gap](https://www.growth-memo.com/p/the-consensus-gap) (industry study with method; May 11, 2026; US generalization limited).
- [Suggestive] In Ahrefs' analysis published June 12, 2025 (June 2025 data: ~76.7M AI Overviews, 957K ChatGPT prompts, 953.5K Perplexity prompts), only 14% of the top-50 most-mentioned sources, i.e. 7 websites, appeared in the top 50 for all three of ChatGPT, Perplexity and Google AI Overviews. Source: [ahrefs.com/blog/top-mentioned-sources-are-not-shared-across-ai-assistants](https://ahrefs.com/blog/top-mentioned-sources-are-not-shared-across-ai-assistants/) (industry study with method; June 12, 2025).
- [Suggestive] Ahrefs (11 Aug 2025) ran 15,000 long-tail prompts through ChatGPT, Gemini, Copilot and Perplexity and found "only 12% of links cited by ChatGPT, Gemini, and Copilot appear in Google's top 10 results", that "Perplexity consistently favors content that ranks well in Google, with 28.6% of its cited URLs landing in the top 10", that ChatGPT in-text citations were 8.00% in Google's top 10, and that "80% of those citations don't rank anywhere in Google for the original query". Source: [ahrefs.com/blog/ai-search-overlap](https://ahrefs.com/blog/ai-search-overlap/) (industry study with method; August 11, 2025; over a year old).
- [Suggestive] Wellows' citation-overlap study (July 29, 2026, updated Aug 6, 2026, by Khadija Zaman) analysed 22.7 million citations across ChatGPT, Gemini, Perplexity, Google AI Overviews and Google AI Mode from January to June 2026, on 531,889 questions where all five engines cited at least one site; it reports that "Perplexity never touches 89.1% of the websites ChatGPT cites" and that "79.6% of the websites cited on a question appear on only one of the five AI engines". Source: [wellows.com/blog/ai-citation-overlap-study](https://wellows.com/blog/ai-citation-overlap-study/) (vendor research with high-level method; July 29, 2026).

Methodology consequence: score and report per engine; never use one engine's citations, or Google rank, as a proxy for another engine.

### 1.6 Base rates: citations and searches are rarer than assumed

- [Suggestive] Similarweb's AI search statistics page (published 29 Jul 2026, covering June 2025 through May 2026) states "Citation presence in US ChatGPT prompts rose from about 1.6% in June 2025 to roughly 6.8% by May 2026", that "Travel & Hospitality prompts carry a citation about 23% of the time, the highest rate Similarweb tracked", and that "Professional Services sits under 4%". Source: [aisearch.similarweb.com/blog/gen-ai-stats](https://aisearch.similarweb.com/blog/gen-ai-stats/) (vendor-tracked panel data; measurement method for "citation presence" not detailed; July 29, 2026).
- [Suggestive] Profound (Brandon Punturo, 3 Feb 2026) analyzed ~730,000 conversations containing at least one web citation from U.S.-based, English-language users on ChatGPT.com, October–December 2025. It states: "About 18% of ChatGPT conversations trigger at least one web search. That rate held steady across all three months we studied," and "Turn 1 is 2.5× more likely to trigger citations than turn 10, and nearly 4× more likely than turn 20." Source: [tryprofound.com/blog/chatgpt-citation-sources](https://www.tryprofound.com/blog/chatgpt-citation-sources) (vendor research with partial method; 3 Feb 2026). (partially verified: The 18% and 2.5× figures are verbatim. The dataset was misdescribed: the page says '~730,000 conversations containing at least one web citation', not '~700,000+' conversations generally — the researcher rounded a number and dropped the qualifier. The page text retrieved does not state the total conversation pool the 18% was computed over or how the conversations were obtained (e.g., panel/clickstream), so the denominator is unstated. Vendor research with partial method description.)
- See SOCi's local base rate (6.5% of the time in AI recommendations versus 36% in Google's 3-Pack) in Section 5 ([soci.ai](https://www.soci.ai/blog/the-challenge-of-ai-visibility-for-brands-part-1/)).

Methodology consequence: for ChatGPT, "no citation" is not "not visible"; brand mentions in answer text are the main measurable outcome, and first-turn research-starting prompts ("what is", "how to", "best") are the ones that trigger search.

### 1.7 Gaps the research could not close

No fetched study isolates what drives Claude citations or mentions for local businesses; no study is specific to small or local businesses at SMB scale; no interventional study exists on live engines beyond the GEO paper's Perplexity test ([arxiv.org/html/2311.09735](https://arxiv.org/html/2311.09735)); the only pre-2025 peer-reviewed sources are the GEO paper and the Head-to-Tail benchmark ([arxiv.org/abs/2308.10168](https://arxiv.org/abs/2308.10168), Section 5).

## 2. Engine by engine

### 2.1 ChatGPT (with search)

Crawlers and robots.txt

- [Proven] OpenAI's crawler documentation states "OAI-SearchBot is used to surface websites in search results in ChatGPT's search features. Sites that are opted out of OAI-SearchBot will not be shown in ChatGPT search answers, though can still appear as navigational links." It describes GPTBot as used "to crawl content that may be used in training our generative AI foundation models", and states "we recommend allowing OAI-SearchBot in your site's robots.txt file and allowing requests from our published IP ranges". By OpenAI's own statement, a site that blocks OAI-SearchBot in robots.txt will not be shown in ChatGPT search answers. Source: [developers.openai.com/api/docs/bots](https://developers.openai.com/api/docs/bots) (official engine doc; undated). Verified in the studies, ChatGPT, source-trust and technical batches; merged here. Describing a block as a "hard visibility failure" is interpretation; the documented consequence is exclusion from search answers with navigational links still possible.
- [Proven] The same page states that OAI-SearchBot and GPTBot robots.txt settings are independent ("Each setting is independent of the others – for example, a webmaster can allow OAI-SearchBot in order to appear in search results while disallowing GPTBot"), that "If your site has allowed both bots, we may use the results from just one crawl for both use cases to avoid duplicative crawling," and that "For search results, please note it can take ~24 hours from a site's robots.txt update for our systems to adjust." Source: [developers.openai.com/api/docs/bots](https://developers.openai.com/api/docs/bots) (official engine doc; undated). The "~24 hours" is OpenAI's own approximation.
- [Proven] The same page states: "OpenAI also uses ChatGPT-User for certain user actions in ChatGPT and Custom GPTs. When users ask ChatGPT or a CustomGPT a question, it may visit a web page with a ChatGPT-User agent." It adds "ChatGPT-User is not used for crawling the web in an automatic fashion. Because these actions are initiated by a user, robots.txt rules may not apply. ChatGPT-User is not used to determine whether content may appear in Search." A robots.txt Disallow therefore may not prevent ChatGPT-User from fetching a page during a user-initiated request. Source: [developers.openai.com/api/docs/bots](https://developers.openai.com/api/docs/bots) (official engine doc; undated). Verified in the ChatGPT and technical batches; merged here.

Retrieval backend

- [Suggestive] Peec AI (blog post by Tomek Rudzki, dated Sep 4, 2026) reports that "Between May 21 and July 21, 2026, a field called result_source showed up directly in ChatGPT's server-side events. It only ever carried four values: Labrador, Bright, Oxylabs, and SERP," describing Labrador as OpenAI's own index and the other three as external scraping providers. The post says Labrador "breaks out by categories": General web, PDF, YouTube, News (with last-day / last-7-days / older tiers), arXiv, Wikipedia, Local, Finance (with a separate PDF index), Legal, Medical, Shopping, Images. It also reports that in mid-August 2026 an A/B experiment named "prefer-index-over-serp-v3" "was affecting 8% of chats at the time." Source: [peec.ai/blog/chatgpt-built-its-own-search-index](https://peec.ai/blog/chatgpt-built-its-own-search-index) (GEO-vendor blog based on the author's own inspection of server-sent events; no sample size, account count, or 8% measurement method disclosed; Sep 4, 2026). Bing indexation is therefore not a proxy for ChatGPT retrieval; any "indexed in Bing" criterion is heuristic.
- [Suggestive] Peec AI's Sep 4, 2026 post attributes ChatGPT local results to several sources: Bright ("very likely Bright Data") which "scrapes Google's web results directly, and separately scrapes Google Maps for local listings"; Yelp and TripAdvisor, which the post says "are treated as licensed partners"; and "Two anonymous internal pipes (tagged b1 and b3): b1 surfaces business websites and Facebook pages, b3 routes to Google Maps." Source: [peec.ai/blog/chatgpt-built-its-own-search-index](https://peec.ai/blog/chatgpt-built-its-own-search-index) (vendor observation; the "licensed partner" characterization is Peec's inference from event tags; Sep 4, 2026).
- [Suggestive, older] A Semrush article (Rachel Handley, Aug 6, 2025) quotes OpenAI documentation: "Currently, the only third-party search provider we use for Enterprise and Edu workspaces is Bing, and we will not add other search providers unless we provide notice to you of this change," and states that in ChatGPT search documentation "Bing and Shopify are the only named third-party providers." - [Proven] Perplexity's own engineering article on its Search API (Sep 25, 2025) says the ranking pipeline retrieves and scores results "at both the document and sub-document levels" and is "designed to surface the most atomic units possible to the model, such that downstream consumers can incorporate those precise units without pulling in irrelevant context from elsewhere in the source documents" — a self-contained passage can be selected independently of the rest of the page. Source: [Internet Archive capture of research.perplexity.ai](http://web.archive.org/web/20260602082126id_/https://research.perplexity.ai/articles/architecting-and-evaluating-an-ai-first-search-api) (official engine doc; Sep 25, 2025; live URL returned 403, read from the 2026-06-02 archive capture). - [Proven] The same article says the pipeline includes "prefiltering stages, in which we apply basic heuristics and first-cut filters to remove clearly non-responsive or stale content from the candidate set" before progressively more advanced ranking stages; the article does not define "stale". Source: [Internet Archive capture of research.perplexity.ai](http://web.archive.org/web/20260602082126id_/https://research.perplexity.ai/articles/architecting-and-evaluating-an-ai-first-search-api) (official engine doc; Sep 25, 2025).

This passage is about index storage tiering (hot vs cold/warm), not final ranking. Source: [Internet Archive capture of research.perplexity.ai](http://web.archive.org/web/20260602082126id_/https://research.perplexity.ai/articles/architecting-and-evaluating-an-ai-first-search-api) (official engine doc; Sep 25, 2025).

### 2.3 Gemini, Google AI Overviews and AI Mode

- [Proven] Google's AI features documentation (last updated 2025-12-10) states: "There are no additional requirements to appear in AI Overviews or AI Mode, nor other special optimizations necessary"; "To be eligible to be shown as a supporting link in AI Overviews or AI Mode, a page must be indexed and eligible to be shown in Google Search with a snippet, fulfilling the Search technical requirements. Source: [developers.google.com/search/docs/appearance/ai-features](https://developers.google.com/search/docs/appearance/ai-features) (official engine doc; last updated 2025-12-10). ## 4. Technical AI readiness signals

### 4.1 robots.txt and crawler access

- OpenAI: OAI-SearchBot governs ChatGPT search appearance; GPTBot governs training; settings independent; ~24 hours to adjust; ChatGPT-User fetches may ignore robots.txt and are not used to decide search appearance ([developers.openai.com/api/docs/bots](https://developers.openai.com/api/docs/bots), Section 2.1). Evidence-backed checks: OAI-SearchBot not disallowed (hard requirement for ChatGPT search answers); GPTBot reported separately as a training opt-out; a ChatGPT-User block is not a search-eligibility signal.
- Perplexity: PerplexityBot allowed in robots.txt is recommended "to ensure your site appears in search results"; Perplexity-User "generally ignores robots.txt rules" ([docs.perplexity.ai/guides/bots](https://docs.perplexity.ai/guides/bots), Section 2.2). Cloudflare's finding that content blocked by robots.txt still appeared in Perplexity answers makes robots.txt neither a guarantee of exclusion nor a prerequisite for inclusion ([blog.cloudflare.com](https://blog.cloudflare.com/perplexity-is-using-stealth-undeclared-crawlers-to-evade-website-no-crawl-directives/)).
- Anthropic: ClaudeBot (training), Claude-User (user fetches) and Claude-SearchBot (search index) are separate tokens; all honor robots.txt and Crawl-delay; IP blocking may not persist; IP list at claude.com/crawling/bots.json ([support.claude.com](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler), Section 2.4). Evidence-backed checks: Claude-SearchBot and Claude-User not disallowed.
- Google: Googlebot access plus indexability and snippet eligibility are the only requirements for AI Overviews and AI Mode ([developers.google.com](https://developers.google.com/search/docs/appearance/ai-features)); Google-Extended has no user agent, does not affect Search inclusion or ranking ([developers.google.com](https://developers.google.com/search/docs/crawling-indexing/google-common-crawlers)), but a Google-Extended disallow excludes pages from Grounding with Google Search on the Gemini Enterprise Agent Platform ([docs.cloud.google.com](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-google-search)). Report Googlebot and Google-Extended as two separate findings.
- [Proven] Google's robots.txt documentation states "Google's crawlers treat all 4xx errors, except 429, as if a valid robots.txt file didn't exist", that "Google enforces a robots.txt file size limit of 500 kibibytes (KiB). Content which is after the maximum file size is ignored", and that "Google generally caches the contents of robots.txt file for up to 24 hours, but may cache it longer in situations where refreshing the cached version isn't possible." Source: [developers.google.com/search/docs/crawling-indexing/robots/robots_txt](https://developers.google.com/search/docs/crawling-indexing/robots/robots_txt) (official engine doc; last updated 2026-08-31). A missing robots.txt is not a blocker for Google; a robots.txt over 500 KiB or returning 5xx is a defect.
- Pattern across engines (researcher synthesis from the documents above): user-initiated fetchers (ChatGPT-User "robots.txt rules may not apply", Perplexity-User "generally ignores robots.txt rules") are documented as not reliably honoring robots.txt, whereas Anthropic states all its bots honor it. A robots.txt Disallow is evidence-backed as a control for training and search crawlers, not for live-answer citations on ChatGPT or Perplexity.

CDN and WAF blocking

- [Proven] Cloudflare's press release dated July 1, 2025 announced it is "the first Internet infrastructure provider to block AI crawlers accessing content without permission or compensation, by default", and stated "Upon sign-up with Cloudflare, every new domain will now be asked if they want to allow AI crawlers, giving customers the choice upfront to explicitly allow or deny AI crawlers access", so "every new domain starts with the default of control"; "Customers can easily check their settings and enable crawling at any time." The release does not say that owners block AI bots unknowingly. Source: [cloudflare.com/press-releases/2025](https://www.cloudflare.com/press-releases/2025/cloudflare-just-changed-how-ai-crawlers-scrape-the-internet-at-large/) (vendor press release; July 1, 2025). (partially verified: Reachable; quote and date verbatim; 'by default' blocking language confirmed. The claim's conclusion 'sites on Cloudflare may block AI bots without the owner knowing' is not on the page: the page says owners are asked and choose upfront and can change settings any time. Removed that inference. Vendor press release, not a study.)
- [Proven] A Cloudflare blog post published July 1, 2026 defines three bot classifications (Search: "Any behavior that collects or indexes your content, so it can answer questions about it later"; Agent: "Automated behavior that is acting, usually in real time, on a person's behalf"; Training: "A crawler taking your content to train or fine-tune a model") and states "On September 15, 2026, we'll be setting new defaults for each of these three classifications. For all new domains onboarding to Cloudflare, the categories of Training and Agent will be blocked by default on the pages that display ads, while Search will remain allowed by default." It also warns "Multi-purpose crawlers such as Googlebot, Applebot, and BingBot will be blocked by customers who have selected to block Training." Source: [blog.cloudflare.com/content-independence-day-ai-options](https://blog.cloudflare.com/content-independence-day-ai-options/) (vendor policy announcement; scope is new domains; July 1, 2026). The audit should test actual HTTP responses to AI crawler user agents (403 or challenge pages) rather than rely on robots.txt alone, and note that the Search/Agent/Training classification of each bot is Cloudflare's, not the engines'.

### 4.2 llms.txt

- [Proven] Google's AI optimization guide: creating LLMS.txt or similar files "will neither harm nor help your site's visibility or rankings in Google Search, as Google Search ignores them" ([developers.google.com](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), last updated 2026-07-10).
- [Proven, older] Search Engine Roundtable (Barry Schwartz, June 18, 2025) reported a social-media remark by Google's John Mueller: "FWIW no AI system currently uses llms.txt", adding that consumer LLMs/chatbots "will fetch your pages - for training and grounding, but none of them fetch the llms.txt file" and that this is "super-obvious if you look at your server logs." This is an informal personal statement reported second-hand, not official Google documentation, and was current as of June 2025. Source: [seroundtable.com/google-ai-llms-txt-39607](https://www.seroundtable.com/google-ai-llms-txt-39607.html) (news; June 18, 2025).
- [Suggestive] SE Ranking (published 7 Nov 2025) analyzed "nearly 300,000 domains" using Spearman correlation, XGBoost regression and SHAP analysis and reports: "There's no correlation between AI citations and LLMs.txt. Both statistical analysis and machine learning showed no effect of LLMs.txt on how often a domain is cited by LLMs." The page also notes that "there's no confirmation that LLMs.txt affects how ChatGPT ranks or cites content." Source: [seranking.com/blog/llms-txt](https://seranking.com/blog/llms-txt/) (industry study with method; November 7, 2025). (partially verified: Page reachable; quote verbatim; methods and OpenAI note confirmed. The claim rounds 'nearly 300,000 domains' to '300,000'; corrected to the page's wording. Vendor study with described method.)
- No OpenAI or Anthropic statement about consuming llms.txt was found. Verdict: llms.txt presence is heuristic at most, unweighted or informational.

### 4.3 Structured data

- [Proven] Google: "Structured data isn't required for generative AI search, and there's no special schema.org markup you need to add" ([developers.google.com](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)); the only AI-features advice is "Making sure your structured data matches the visible text on the page" ([developers.google.com](https://developers.google.com/search/docs/appearance/ai-features)).
- [Proven] A Microsoft Advertising blog post dated October 8, 2025 by Krishna Madhavan (Principal Product Manager, Microsoft Bing) on optimizing content for inclusion in AI search answers states "Schema is a type of code that helps search engines and AI systems understand your content", advises "Ensure crawlability, metadata, and internal linking remain the baseline", says "Your page title, description, and H1 tag ... are important signals AI systems use to interpret purpose and scope", and says "Make answers snippable: Use concise, self-contained phrasing in lists, Q&As, and tables." It refers to "Assistants like Copilot" parsing content into structured pieces. This is advisory guidance, not a measured study. Source: [about.ads.microsoft.com](https://about.ads.microsoft.com/en/blog/post/october-2025/optimizing-your-content-for-inclusion-in-ai-search-answers) (official engine guidance; October 8, 2025). Label as guidance, not measured effect.
- Correlational evidence is mixed: GEO-16 found Structured Data among the strongest associations with citation on Brave, AI Overviews and Perplexity ([arxiv.org/abs/2509.10762](https://arxiv.org/abs/2509.10762)); SE Ranking found pages with FAQ schema averaged fewer ChatGPT citations than pages without (researcher notes referencing [seranking.com](https://seranking.com/blog/how-to-optimize-for-chatgpt/); the exact FAQ figures were not among the verified claims). Net: a schema criterion is heuristic; "structured data matches visible text" is the only evidence-backed formulation.

### 4.4 Rendering and fetch constraints

- [Proven, older] A Vercel blog post co-authored with MERJ, published December 17, 2024, based on log monitoring of nextjs.org and the Vercel network "for the past few months" (including 569 million GPTBot and 370 million Claude requests in one month), stated "None of the major AI crawlers currently render JavaScript", listing OpenAI (OAI-SearchBot, ChatGPT-User, GPTBot), Anthropic (ClaudeBot), Meta (Meta-ExternalAgent), ByteDance (Bytespider) and Perplexity (PerplexityBot); it said "AppleBot renders JavaScript through a browser-based crawler, similar to Googlebot" and recommended "Prioritize server-side rendering for critical content." This finding is from late 2024 and may no longer reflect current crawler behavior. Source: [vercel.com/blog/the-rise-of-the-ai-crawler](https://vercel.com/blog/the-rise-of-the-ai-crawler) (vendor post with stated log method; ~21 months old; December 17, 2024).
- Anthropic's API web fetch tool "currently does not support websites dynamically rendered with JavaScript" and handles only text, HTML and PDF ([platform.claude.com](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool), Section 2.4). Brave's discovery double-fetch "reads raw HTML off the wire", aborts after 10 seconds and refuses responses over 2 MB ([merj.com](https://merj.com/blog/how-brave-search-discovers-new-pages)). A single observed ChatGPT case fell back to citing G2 when a vendor's pricing was loaded with JavaScript ([suganthan.com](https://suganthan.com/blog/how-chatgpt-picks-sources/)). Gemini's url_context tool processes up to 20 URLs per request with a 34MB per-URL cap and does not support paywalled content ([ai.google.dev](https://ai.google.dev/gemini-api/docs/url-context), Section 8.3).
- [Proven] Google's Googlebot documentation states "Googlebot crawls the first 2MB of a supported file type, and the first 64MB of a PDF file", that "The file size limit is applied on the uncompressed data", that "Each resource referenced in the HTML (such as CSS and JavaScript) is fetched separately, and each resource fetch is bound by the same file size limit that applies to other files (except PDF files)", and that "Once the cutoff limit is reached, Googlebot stops the fetch and only sends the already downloaded part of the file for indexing consideration." Source: [developers.google.com/search/docs/crawling-indexing/googlebot](https://developers.google.com/search/docs/crawling-indexing/googlebot) (official engine doc; last updated 2026-02-03). No OpenAI, Anthropic, Perplexity or Bing document states a fetch size or timeout, so AI-crawler size and time thresholds are heuristic.
- [Proven] Google's paywalled-content structured data documentation states "This structured data helps Google differentiate paywalled content from the practice of cloaking, which violates spam policies", instructs "Set the isAccessibleForFree property to false to specify that this section is behind a paywall", describes cssSelector as "A CSS selector that references the class name that you set in the HTML to specify the paywalled section", and says "If you want Google to crawl and index your content, including the paywalled sections, make sure Googlebot ... can access your page." Source: [developers.google.com — paywalled content](https://developers.google.com/search/docs/appearance/structured-data/paywalled-content) (official engine doc; last updated 2026-09-08). No OpenAI, Anthropic or Perplexity documentation on paywall handling was found.

Recommendation: label "key business facts present in raw HTML without JavaScript" as evidence-backed for the Claude API fetch path and Brave, and dated for other crawlers; have the audit measure it directly (compare raw HTML text to rendered DOM text) rather than assume.

### 4.5 Snippet controls

- Google: nosnippet, data-nosnippet, max-snippet and noindex apply to AI formats; "More restrictive permissions will limit how your content is featured in our AI experiences" ([developers.google.com blog](https://developers.google.com/search/blog/2025/05/succeeding-in-ai-search), [developers.google.com ai-features](https://developers.google.com/search/docs/appearance/ai-features)).
- [Proven] Bing's Webmaster blog (October 15, 2025) states "When Bing crawls your site, any content marked with data-nosnippet is still indexed normally, but it will be excluded from snippets and AI summaries", that the attribute keeps marked sections from appearing "in Bing Search snippets or AI-generated answers", and that this applies "across Bing Search and Copilot experiences powered by Bing." Source: [blogs.bing.com — data-nosnippet](https://blogs.bing.com/webmaster/October-2025/Bing-Introduces-Support-for-the-data-nosnippet-HTML-Attribute) (official engine doc; October 15, 2025). Flag nosnippet, data-nosnippet wrapping main content, or low max-snippet values as evidence-backed negatives for Google and Bing AI answers.

### 4.6 Freshness

- Perplexity's pipeline removes "clearly non-responsive or stale content" in prefiltering and schedules re-indexing by "importance and likely update frequency"; "stale" is undefined ([Internet Archive capture of research.perplexity.ai](http://web.archive.org/web/20260602082126id_/https://research.perplexity.ai/articles/architecting-and-evaluating-an-ai-first-search-api)). Claude's search results expose page_age, "When the site was last updated", with no statement that it affects ranking ([platform.claude.com](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)).
- [Suggestive] An Ahrefs study by Ryan Law (July 28, 2025) using Ahrefs Brand Radar data on "16.975 million cited URLs from across ChatGPT, Perplexity, Gemini, Copilot, AI Overviews, and ... organic Google SERPs" states "The average age of URLs cited by AI assistants is 1064 days, compared to 1432 days for URLs in organic SERPs—25.7% 'fresher'", and that "ChatGPT shows the strongest preference for new content, preferring to cite URLs that are 393 days newer than organic Google results." Its data table, however, lists Organic SERP at 1416 days and Google AIO (top 3) at 1432 days, so the organic figure is internally inconsistent (1432 in the headline sentence vs 1416 in the table); AI Overviews' average is within 16 days of organic, and the article says "Google's AI Overviews and organic search results are the most likely to cite older pages." Page age was measured as the date first seen by Ahrefs' crawler. Source: [ahrefs.com/blog/do-ai-assistants-prefer-to-cite-fresh-content](https://ahrefs.com/blog/do-ai-assistants-prefer-to-cite-fresh-content/) (industry study with method; July 28, 2025). (partially verified: Reachable; quoted sentence verbatim; 16.975M, ChatGPT-strongest, and AIO-matches-organic confirmed. Flagged: the article's own table gives Organic SERP = 1416 and AIO = 1432, contradicting the headline '1432 days for organic'. Do not cite 1432 as the organic figure without this caveat. Vendor study with a stated method; age is a first-seen proxy, not true publish date.)
- Seer Interactive: 75% of cited pages updated within the last year; 72% look fresh by last update but only 42% were published within the year ([seerinteractive.com](https://www.seerinteractive.com/insights/study-content-recencys-impact-on-ai-visibility-in-2026), Section 1.3). Ahrefs: median cited ChatGPT page around 500 days old; "Relevance still does the heavy lifting" ([ahrefs.com](https://ahrefs.com/blog/why-chatgpt-cites-pages/)).
- Verdict: score visible and machine-readable last-modified signals (schema dateModified, sitemap lastmod) as heuristic; all freshness evidence is correlational.

### 4.7 Sitemaps, IndexNow, indexation channels

- [Proven] Google's sitemap documentation states "All formats limit a single sitemap to 50MB (uncompressed) or 50,000 URLs", that "Google uses the <lastmod> value if it's consistently and verifiably (for example by comparing to the last modification of the page) accurate", and that "Google ignores <priority> and <changefreq> values." Source: [developers.google.com — build sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap) (official engine doc; last updated 2026-07-08). - [Proven] The IndexNow FAQ lists Amazon, Bing, Naver, Seznam.cz, Yandex and Yep as participating search engines (Google is not listed), states "your submission will be shared across all IndexNow-enabled search engines", and states "Submitting a URL does not guarantee immediate indexing. - Brave has no search console, sitemap submission or IndexNow; pages enter its index via around 20 opted-in browser users or one user search on another engine's results page ([merj.com](https://merj.com/blog/how-brave-search-discovers-new-pages)). ## 6. Nondeterminism and measurement practice

### 6.1 What the engines say about determinism

- [Proven] Anthropic's Messages API reference marks the temperature parameter "Deprecated. Models released after Claude Opus 4.6 do not support setting temperature. A value of 1.0 will be accepted for backwards compatibility, all other values will be rejected with a 400 error." Source: [platform.claude.com/docs/en/api/messages](https://platform.claude.com/docs/en/api/messages) (official engine doc; undated). A low temperature cannot be set on current Claude models.
- [Proven] Anthropic's glossary states: "Users may encounter non-determinism in APIs. Even with temperature set to 0, the results will not be fully deterministic and identical inputs may produce different outputs across API calls. This applies both to Anthropic's first-party inference service and to inference through third-party cloud providers." Source: [platform.claude.com/docs/en/about-claude/glossary](https://platform.claude.com/docs/en/about-claude/glossary) (official engine doc; undated).
- [Proven] OpenAI's Chat Completions API reference documents the seed parameter as: "This feature is in Beta. If specified, our system will make a best effort to sample deterministically, such that repeated requests with the same seed and parameters should return the same result. Determinism is not guaranteed, and you should refer to the system_fingerprint response parameter to monitor changes in the backend." The system_fingerprint field "Can be used in conjunction with the seed request parameter to understand when backend changes have been made that might impact determinism." Source: [developers.openai.com/api/docs/api-reference/chat/create](https://developers.openai.com/api/docs/api-reference/chat/create) (official engine doc; undated).
- [Proven, older] OpenAI's cookbook "Reproducible outputs with the seed parameter" states that with matching seed, parameters and system_fingerprint "model outputs will mostly be identical", that "Determinism is not guaranteed", and that "There is a small chance that responses differ even when request parameters and system_fingerprint match, due to the inherent non-determinism of our models." The cookbook targets gpt-4-1106-preview and gpt-3.5-turbo-1106 and references SDK version 1.3.3, i.e. late-2023 material. Source: [developers.openai.com/cookbook](https://developers.openai.com/cookbook/examples/reproducible_outputs_with_the_seed_parameter) (official engine doc; predates current models).

### 6.4 Implications for repeated runs and confidence

1. A single run per prompt is a sample of one and cannot be labeled evidence-backed: the IAB framework states "Single-response measurement is not measurement" ([iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf), Section 7); SparkToro found under a 1-in-100 chance of the same brand list twice ([sparktoro.com](https://sparktoro.com/blog/new-research-ais-are-highly-inconsistent-when-recommending-brands-or-products-marketers-should-take-care-when-tracking-ai-visibility/)).
2. Run-count guidance disagrees: at least 7–8 runs per prompt per day ([arxiv.org/html/2604.07585](https://arxiv.org/html/2604.07585)); 5/10/15 by rigor tier ([arxiv.org/abs/2609.04047](https://arxiv.org/abs/2609.04047)); repeats beyond about five buy almost nothing and breadth (paraphrases, models, languages) matters more ([arxiv.org/html/2607.13304](https://arxiv.org/html/2607.13304)); Evertune samples 100 times ([evertune.ai](https://www.evertune.ai/resources/insights-on-ai/repeated-sampling-enables-geo-action-by-topic-and-prompt)); Peec and Profound run once per day and aggregate over time ([peec.ai](https://peec.ai/for-agencies), [tryprofound.com](https://www.tryprofound.com/blog/is-once-a-day-enough)). A defensible one-off audit policy is 5–10 same-day runs per prompt per engine plus several paraphrases per intent, with the tier disclosed; a one-off audit cannot rely on time aggregation.
3. Binary mention of the tracked business is more stable than the competitor list or sentiment: 77.5% of cells always- or never-mentioned ([arxiv.org/html/2606.20065v1](https://arxiv.org/html/2606.20065v1)) versus recommendation-set rerun Jaccard of 0.50–0.61 ([arxiv.org/abs/2605.27440](https://arxiv.org/abs/2605.27440)) and sentiment 6.7× noisier than mention ([arxiv.org/html/2606.20065v1](https://arxiv.org/html/2606.20065v1)). Report mention rate and sentiment separately; derive competitor sets from repeated runs and multiple phrasings.
4. Citation presence for a specific domain is highly variable between identical runs (21.2% shared domains on ChatGPT, 31.5% on AI Overviews, [parse.gl](https://parse.gl/research/ai-citation-volatility-by-industry); 34–42% day-to-day source overlap, [arxiv.org/html/2604.07585](https://arxiv.org/html/2604.07585)); score citation presence as a frequency over repeats and carry an "as of" date.
5. Report every visibility figure as a range: the IAB says "approximately 22%, plus or minus 4 points based on current measurement precision" is more useful than "a bare 22% that implies false precision" ([iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf)). Only the academic preprints and the GitHub framework noted by the researchers state an interval method; no vendor page fetched publishes its CI computation.
6. Log model identifier, snapshot date, reasoning effort, tool_choice, search context size and user_location for every call; drift diagnostics depend on it ([arxiv.org/abs/2609.04047](https://arxiv.org/abs/2609.04047)).

## 7. How other GEO / AI visibility tools structure scores and reports

### 7.1 The IAB measurement framework (industry standard, normative)

- [Proven] The IAB framework "Measuring Visibility in the AI Era" (Published August 2026) sets a Criteria Matrix with two tiers, Directional and Decision-Grade. In the Query Volume row, the Directional cell says the framework "treats fewer than 50 queries per measurement program as exploratory rather than directional, since query volumes below that floor cannot meaningfully characterize a category." In the Sample Size row, the Directional cell requires "Multiple responses per query to capture typical variation" and the Decision-Grade cell requires "Enough responses per query to establish a stable distribution; provider must disclose responses per query and how consistency is determined." Elsewhere the document states "Single-response measurement is not measurement... any metric derived from one response per query reflects a sample of one." Source: [iab.com — Measuring Visibility in the AI Era (PDF)](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf) (industry-body framework, normative, not an empirical measurement; August 2026). Minimum prompt count for the audit: at least 50.
- [Proven] In the IAB matrix's Reproducibility row, the Directional cell says "Results will vary across runs; provider must document how much variation is typical" and the Decision-Grade cell says "Provider must define acceptable variation ranges within a 7-day time window, report confidence levels, and maintain a documented process for verifying consistency." The Executive Reporting Guidance states "AI visibility data is probabilistic, non-deterministic, and sensitive to query composition, model version, and platform behavior" and says a Share of Voice figure reported as "approximately 22%, plus or minus 4 points based on current measurement precision" is more useful than "a bare 22% that implies false precision." The document also recommends "reporting results as a range rather than a single number" and "reporting trends over time rather than point-in-time snapshots, always disclosing the measurement tier." Source: [iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf) (August 2026).
- [Proven] The IAB framework states: "This framework requires that any provider offering a composite index disclose the full weighting methodology, the normalization method used (e.g., max-normalized, z-scored, percentile rank), the individual metric values that feed the composite, and the limitations of the aggregation approach. The component metrics defined in this framework are the authoritative measurement vocabulary; composite scores are a presentation layer, and the underlying data must always be accessible." The preceding sentence says composite scores "can be useful for tracking overall trajectory, but they require weighting decisions that materially affect the output." Source: [iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf) (August 2026). This governs the 0-100 six-pillar score: publish pillar weights, normalization, and the raw component values behind each pillar.
- [Proven] IAB defines Mention Rate as "responses containing a brand mention divided by total responses"; Citation Rate as "responses containing a brand citation divided by total responses"; and Share of Voice as "Brand mentions as a proportion of all brand mentions within a defined competitive category." A citation is "a linked reference (containing a hyperlink) or a named reference (identifying the brand by name as a source)"; implied citations without explicit attribution are excluded because they cannot be measured consistently. Providers must disclose how the competitive category is defined and how the total category mention universe is sized; "Results are sensitive to query set composition, and different query sets will produce different rates". Source: [iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf) (August 2026).
- [Proven] IAB states: "Presence metrics such as Mention Rate and Citation Rate are measurable at directional scale and suitable for trend monitoring. Prominence and Portrayal metrics, including Position, Sentiment, Framing, and Recommendation Strength, involve methodological judgment calls that amplify variance and require higher reproducibility for decision-grade use." Persuasion metrics such as Post-Citation CTR "are currently directional for most implementations." Buyers should "evaluate provider claims about any individual metric against the tier thresholds... not assume that a provider's overall tier classification applies uniformly to every metric." Source: [iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf) (August 2026). Position- and sentiment-derived criteria are heuristic unless reproducibility is demonstrated.

### 7.2 Vendor metric definitions (they disagree on denominators)

- [Proven] Peec AI's documentation defines the Visibility Score as the percentage of AI responses that mention the brand: "Visibility Score = (Number of responses mentioning your brand / Total responses) × 100", with all tracked responses as the denominator. Source: [docs.peec.ai/metrics/brand-metrics/visibility](https://docs.peec.ai/metrics/brand-metrics/visibility) (vendor documentation; undated). Consistent with IAB Mention Rate.
- [Proven] Profound's help center defines Visibility Score as "the number of responses that include your brand divided by the total number of responses that include at least one brand", a denominator that differs from Peec's and the IAB's Mention Rate (which divide by all responses). Profound separately defines Share of Voice as "the number of responses that mention your brand divided by the total number of brand mentions across all responses" and a Citation as "a reference or link to a specific webpage, article, or resource within an answer engine response." Source: [help.tryprofound.com](https://help.tryprofound.com/articles/3443229936-answer-engine-insights-overview) (vendor documentation; undated). Excluding brand-free answers inflates the score relative to the IAB/Peec definition; the audit must state which denominator it uses.
- [Proven] Ahrefs Brand Radar help page states: "A single mention is counted when a brand appears at least once in an AI generated response"; "Impressions are calculated by summing up search volumes (based on Google) of prompts where your brand appears as an AI Answer"; and AI Share of Voice "is a brand's percentage share of impressions compared to other tracked brands." Because SoV is a share of impressions and impressions are summed Google search volumes, Ahrefs' SoV is volume-weighted rather than a raw mention-count share. Source: [help.ahrefs.com — AI visibility metrics](https://help.ahrefs.com/en/articles/15501968-ai-visibility-metrics) (vendor documentation; undated; Google keyword volume applied to AI prompts is not justified on the page). The audit must state whether prompts are equally weighted or demand-weighted.
- [Proven] Conductor's AI Search FAQ states "Conductor will generate up to 100 prompts for a topic" using domain context (organization description, industry, recent news, themes), keyword analysis (highest-volume tracked keywords) and content analysis (semantic clustering of site pages), then assigns a search intent and persona to each generated prompt. ### 7.6 Contradictions between vendors and the standard

- Visibility denominator: Peec, IAB and Wix divide by all responses or questions ([docs.peec.ai](https://docs.peec.ai/metrics/brand-metrics/visibility), [iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf), [support.wix.com](https://support.wix.com/en/article/ai-visibility-overview)); Profound divides by responses containing at least one brand ([help.tryprofound.com](https://help.tryprofound.com/articles/3443229936-answer-engine-insights-overview)).
- Share-of-voice weighting: Peec, Conductor, AthenaHQ and IAB use mention counts; Ahrefs weights by Google search volume ([help.ahrefs.com](https://help.ahrefs.com/en/articles/15501968-ai-visibility-metrics)).
- Repeat runs: Evertune argues for 100 repeats ([evertune.ai](https://www.evertune.ai/resources/insights-on-ai/repeated-sampling-enables-geo-action-by-topic-and-prompt)); Profound argues once a day suffices at the aggregate level ([tryprofound.com](https://www.tryprofound.com/blog/is-once-a-day-enough)). The IAB says quantitative thresholds for acceptable variability remain an open working-group question ([iab.com PDF](https://www.iab.com/wp-content/uploads/2026/07/IAB_Measuring_Visibility_in_the_AI_Era_August_2026-1.pdf)).
- No peer-reviewed study on tool scoring structures was found; "proven" in this section means verbatim in product documentation or the standard's text.

## 8. API reference for the provider adapters

All statements in this section are from official provider documentation fetched on 2026-09-29 unless marked otherwise. Doc pages on platform.claude.com, developers.openai.com and docs.perplexity.ai show no publication dates; Google pages show "Last updated" dates.

### 8.1 OpenAI Responses API web search (ChatGPT adapter)

Endpoint and tool configuration

- Endpoint: POST https://api.openai.com/v1/responses; platform.openai.com/docs/* now redirects to developers.openai.com/api/docs/*, and all citations use the redirected URLs ([developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)).
- [Proven] For new Responses API integrations, OpenAI's web search guide says to use { "type": "web_search" }; the earlier web_search_preview tool remains available for legacy integrations but does not support newer controls such as filters, external_web_access, and return_token_budget. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). The API reference's tool-object schema lists external_web_access and filters only on the non-preview tool and does not list return_token_budget on either tool object, so return_token_budget is documented in the guide only.
- [Proven] The Responses API reference exposes two tool objects: the web search tool ("One of web_search or web_search_2025_08_26"), with properties type, external_web_access, filters, search_context_size and user_location; and the web search preview tool ("One of web_search_preview or web_search_preview_2025_03_11"), with properties type, search_content_types, search_context_size and user_location. Under both, search_context_size is described as "One of low, medium, or high. medium is the default." Source: [developers.openai.com — responses/create reference](https://developers.openai.com/api/docs/api-reference/responses/create).
- [Proven] The guide says to use search_context_size low for simple lookups, medium for a balanced default, and high when the answer may require more detail from search results, and that this setting does not set an exact token count or guarantee a specific number of sources or citations. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). Fix one context size across runs; citation-count criteria are heuristic because counts are not controllable.
- [Proven] The guide states that with tool_choice: "auto" search is optional, and to use tool_choice: "required" or a specific web search tool choice when search must run. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). Record which was used; "auto" is closer to ChatGPT's optional-search behaviour.
- [Proven] The guide states that with the filters parameter you can configure up to 100 allowed_domains or up to 100 blocked_domains; domains should omit the HTTP or HTTPS prefix (e.g. openai.com instead of https://openai.com/); this approach also includes subdomains in the search; and domain filtering is only available in the Responses API with the web_search tool. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). Visibility runs should not use allowed_domains.
- Other verified parameters from the researcher notes: external_web_access boolean ("Defaults to true when omitted. When false, the web search tool runs in offline/cache-only mode and will not fetch new external content"); return_token_budget accepts only default or unlimited and applies only to GPT-5+ reasoning web search; search_content_types may include image ([developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)).

Localization

- [Proven] The API reference says user_location is the approximate location of the user; if omitted or null it defaults to the United States; to avoid this fallback pass {"type": "approximate"} without location fields; to localize results provide the relevant fields: country (two-letter ISO country code, e.g. US), city (free text, e.g. San Francisco), region (free text, e.g. California) and timezone (IANA timezone, e.g. America/Los_Angeles). Source: [developers.openai.com — responses/create reference](https://developers.openai.com/api/docs/api-reference/responses/create).
- [Proven] The guide states: "To refine search results based on geography, you can specify an approximate user location using country, city, region, and/or timezone." Country is a two-letter ISO code, city and region are free-text strings (example: Minneapolis and Minnesota), timezone is an IANA timezone, and the location type is "approximate". The docs add: "Note that user location is not supported for deep research models using web search." Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). For "best X near Y" prompts set user_location to the business's market.

Where citations live

- [Proven] The guide states that a response using the web search tool includes (a) a web_search_call output item with the search call ID and the action taken in web_search_call.action, and (b) a message output item whose text is in message.content[0].text and whose cited URLs appear as annotations in message.content[0].annotations; inline citations are included by default, and the url_citation annotation object contains the URL, title and location of the cited source. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search).
- [Proven] In the Responses API reference, the url_citation annotation has end_index (number, "The index of the last character of the URL citation in the message"), start_index (number, "The index of the first character of the URL citation in the message"), title (string, "The title of the web resource"), type ("url_citation", "Always url_citation") and url (string, "The URL of the web resource"). Source: [developers.openai.com — responses/create reference](https://developers.openai.com/api/docs/api-reference/responses/create). Character spans: yes (start_index and end_index in the message text).
- [Proven] Per the guide, the sources field returns the complete list of URLs the model consulted when forming its response, whereas inline citations show only the most relevant references; "The number of sources is often greater than the number of citations"; real-time third-party feeds surfaced in sources are labeled oai-sports, oai-weather, or oai-finance; and the sources field is available with both the web_search and web_search_preview tools. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). Record both annotations (cited) and sources (consulted); exclude oai-* feed entries when counting third-party sources.
- [Proven] In the API reference, passing include: ["web_search_call.action.sources"] ("Include the sources of the web search tool call") returns, on the search action of the web_search_call item, an optional sources array of objects with type ("url", "The type of source. Always url") and url (string, "The URL of the source"). Source: [developers.openai.com — responses/create reference](https://developers.openai.com/api/docs/api-reference/responses/create). No populated JSON example of sources exists in the docs; the shape comes from the schema.
- [Proven] The guide lists web_search_call.action as one of: search ("represents a web search. It will usually (but not always) includes the search queries which were searched. Search actions incur a tool call cost"), open_page ("represents a page being opened. Supported in reasoning models"), and find_in_page ("represents searching within a page. Supported in reasoning models"). The page states that search actions incur a tool call cost; it does not state whether open_page or find_in_page are charged. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). (partially verified: Page reachable; the quoted text is verbatim. The word 'only' in 'only search actions incur the tool-call charge' is an inference: the page says search actions incur a tool call cost but is silent on the cost of open_page/find_in_page.) Count web_search_call items with action.type == search for cost accounting. The API reference marks action.search.query as Deprecated and adds queries (array of string); parse queries first, fall back to query ([developers.openai.com — responses/create reference](https://developers.openai.com/api/docs/api-reference/responses/create), researcher note).
- [Proven] The guide states that when displaying web results or information contained in web results to end users, inline citations must be made clearly visible and clickable in your user interface. Source: [developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search). Customer-facing report UI must render cited sources as links.

Gotchas

- Annotation shape differs by API: Responses puts start_index/end_index/url/title directly on the annotation object; Chat Completions nests them under a url_citation sub-object ([developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)).
- search_context_size does not guarantee citation counts and tool_choice auto lets the model skip search, so any criterion based on the number of citations or presence of a web_search_call is heuristic unless the run pins tool_choice, context size, model and user_location and reports them ([developers.openai.com — web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)).
- Omitting user_location defaults to the United States ([developers.openai.com — responses/create reference](https://developers.openai.com/api/docs/api-reference/responses/create)).
- The guide's "ZDR and data residency" section rendered empty in the fetched HTML, so zero-data-retention behavior for web search could not be verified (researcher note).

### 8.2 Anthropic Messages API web search (Claude adapter)

Endpoint, headers and tool versions

- Endpoint: POST https://api.anthropic.com/v1/messages with headers x-api-key, anthropic-version and content-type: application/json ([platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)).
- [Proven] When making API requests you must send an anthropic-version request header, for example anthropic-version: 2023-06-01; the client SDKs set it automatically. The version history lists 2023-06-01 as the latest version (after 2023-01-01), and Anthropic recommends using the latest version. Source: [platform.claude.com/docs/en/api/versioning](https://platform.claude.com/docs/en/api/versioning).
- [Proven] The tool reference lists three current web search tool versions, web_search_20250305, web_search_20260209 and web_search_20260318, with Beta header "None". Under "Capability-keyed" it states that web_search_20260209 adds dynamic content filtering over its predecessor and web_search_20260318 adds response-inclusion control, and that "in each case, both the new and old versions are current; which one you use depends on whether you need the new capability." The web search tool page labels web_search_20250305 as "basic web search". Source: [platform.claude.com — tool reference](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-reference).
- [Proven] All web search tool versions accept allowed_callers. On web_search_20260209 and later it defaults to ["code_execution_20260120"] instead of ["direct"], so dynamic filtering runs from inside code execution, which the API provisions automatically. To call web search directly without dynamic filtering, set allowed_callers: ["direct"]; models that don't support programmatic tool calling require this setting, and without it the API returns a 400 error that tells you to set it. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Adapter: either use web_search_20250305 (defaults to direct) or web_search_20260318 with allowed_callers ["direct"] to get the simple response shape.
- [Proven] The programmatic tool calling page states that Claude Haiku 4.5 accepts the code_execution_20260120 and later tool versions but doesn't support programmatic tool calling, and lists the supported models as claude-fable-5-1, claude-mythos-5-1, claude-fable-5, claude-mythos-5, claude-opus-5-5, claude-opus-5, claude-opus-4-8, claude-opus-4-7, claude-opus-4-6, claude-opus-4-5-20251101, claude-sonnet-5-5, claude-sonnet-5, claude-sonnet-4-6 and claude-sonnet-4-5-20250929. Together with the web search page, this implies Haiku 4.5 must set allowed_callers: ["direct"] to use web_search_20260209 or later. Source: [platform.claude.com — programmatic tool calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling). (partially verified: Page reachable; the Haiku 4.5 sentence is verbatim and the 14-model list matches the page's supportedModels metadata exactly. The consequence for web search on Haiku 4.5 is not stated on the cited page; it follows from combining it with the web-search-tool page (fetched, quote confirmed). No publication date shown.) Whether Haiku 4.5 supports basic web search is not explicitly written on any fetched page; verify with a live call before committing the cost model to Haiku (researcher note).
- [Proven] max_uses limits the number of searches performed per request; if Claude attempts more searches than allowed, the web_search_tool_result is an error with the max_uses_exceeded error code (the API still returns a 200 response with the error inside the result block). Simple factual queries typically use 1–3 searches and comparative or multi-entity research can use 10 or more. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Set max_uses explicitly per prompt to bound cost; the 1-3 / 10+ figures are guidance, not a measured study.

Localization and domain filters

- [Proven] The user_location parameter localizes search results. Its type must be "approximate", and you provide at least one of city, region, country or timezone. country is a two-letter ISO 3166-1 alpha-2 code and the API rejects unsupported country codes with a 400 error; timezone is an IANA timezone ID. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Schema (API reference) limits city/region/timezone to 1-255 chars and country to exactly 2 (researcher note from [platform.claude.com/docs/en/api/messages](https://platform.claude.com/docs/en/api/messages)).
- [Proven] For web search and web fetch domain filtering: you can use either allowed_domains or blocked_domains but not both in the same request; domains should not include the HTTP/HTTPS scheme; subdomains are automatically included (example.com covers docs.example.com) while a specific subdomain entry restricts results to only that subdomain; subpaths are supported for web search and match anything after the path (web fetch matches on the domain only); wildcards are not allowed in the domain itself, only in the path after it; invalid domain formats are rejected at request time with a 400 invalid_request_error; and request-level allowed_domains must be a subset of any organization-level allow list. Source: [platform.claude.com — server tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/server-tools). Do not use allowed_domains for visibility tests.

Where citations live

- [Proven] Citations are always enabled for web search. Each web_search_result_location citation on a text block includes url, title, encrypted_index ("a reference that must be passed back for multi-turn conversations") and cited_text ("up to 150 characters of the cited content"); the cited_text, title and url citation fields do not count toward input or output token usage. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Character spans: no start/end indices for web search; the citation is attached to the text block it supports and carries a 150-character snippet (document citations use char_location with character indices, see web fetch below).
- [Proven] In the documented example response, a search appears as a server_tool_use block (id "srvtoolu_01WYG3ziw53XMcoyKL4XcZmE", name "web_search", input {"query": ...}) followed by a web_search_tool_result block with the same tool_use_id whose content is a list of web_search_result items. Search results include url, title, page_age ("when the site was last updated") and encrypted_content ("encrypted content that you must pass back in multi-turn conversations"). Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). web_search_result URLs are the retrieved candidate set; web_search_result_location URLs are the cited set; log both. Parser must tolerate null page_age and null title (API reference schema: title string or null, minLength 1, maxLength 512; page_age string or null).
- [Proven] The web search tool page states that when a search runs through dynamic filtering, the response also contains the code execution tool's result blocks, and each nested server_tool_use and web_search_tool_result pair carries a caller field identifying the code execution call that made it; the direct-search example has no caller field. The exact caller shape {"type": "code_execution_20260120", "tool_id": "srvtoolu_..."} is documented on the programmatic tool calling page for programmatically invoked tool_use blocks, and the tool reference states that response blocks always tag the caller as code_execution_20260120. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). (partially verified: Page reachable; quoted sentence verbatim. The cited page does not show the caller object's shape for web search blocks; the shape is shown on the programmatic-tool-calling page (fetched) for client tool_use blocks. No publication date shown.) Iterate all content blocks recursively and key results by tool_use_id.
- [Proven] When the web search tool encounters an error, the Claude API still returns a 200 response; the error appears as a web_search_tool_result whose content is a single object {"type": "web_search_tool_result_error", "error_code": ...} rather than a list of result blocks. Documented codes are too_many_requests, invalid_tool_input, max_uses_exceeded, query_too_long, request_too_large and unavailable. A search that succeeds but matches no results returns an empty content list, not an error. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Record error_code per search so a too_many_requests run is flagged incomplete rather than "business not mentioned".
- [Proven] To continue a conversation containing search results, send the assistant's content blocks back exactly as received, including each result's encrypted_content; the API decrypts it on later turns. encrypted_index in citations must likewise be passed back for multi-turn conversations. If encrypted_content is missing or modified, the request fails with a 400 validation error. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Persist the raw assistant content JSON per query if follow-up turns are planned.
- [Proven] The API can pause a long-running search turn and return stop_reason "pause_turn"; to continue, send the paused assistant message back unchanged in a new request (the server-tools guide adds that the continuation must include the same tools, or the API returns a validation error). If Claude calls web search and one of your client tools in the same group of parallel tool calls, the API returns stop_reason "tool_use" instead and does not run the search yet; return the client tool results and the search runs on the next request. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Check stop_reason on every response; loop on pause_turn with a cap; avoid mixing client tools into audit prompts.

Each web search counts as one use regardless of the number of results returned, and if an error occurs during web search, the search is not billed. Source: [platform.claude.com — web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool).

- [Proven] The pricing page lists base input / output prices per million tokens of Claude Haiku 4.5 $1 / $5, Claude Sonnet 5.5 $2 / $10, Claude Opus 5.5 $4 / $20 and Claude Fable 5.1 $10 / $50. Web fetch tool (optional "read the business site" step)

- [Proven] The web fetch tool versions web_fetch_20250910, web_fetch_20260209, web_fetch_20260309 and web_fetch_20260318 all remain available; web fetch has no additional charges beyond standard token costs. Unlike web search, citations are optional for web fetch and disabled by default, enabled with "citations": {"enabled": true}; the documented example shows fetched-document citations of type char_location with document_index, document_title, start_char_index, end_char_index and cited_text. - [Proven] Web fetch can only fetch URLs that previously appeared in the conversation: URLs in user messages, in client-side tool results, and from previous web search or web fetch results; URLs that appear only in Claude's own output, only in the system prompt, or only in other server-side tool results are not fetchable (url_not_in_prior_context). url_not_allowed covers URLs blocked by domain filtering rules or by Anthropic-side restrictions such as private addresses, robots.txt and URLs that appear to contain a credential you did not provide. url_too_long applies when a URL exceeds 250 characters. The tool currently does not support websites dynamically rendered with JavaScript. Source: [platform.claude.com — web fetch tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool). Put the site URL in the user message so it is fetchable.

- Web search is not available on Amazon Bedrock; Google Cloud and Azure-hosted Foundry support only web_search_20250305 (researcher note from the web search tool page, [platform.claude.com](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)).

- The query_too_long threshold, the number of results per search, and the maximum length of allowed_domains/blocked_domains on the Messages API are not documented (researcher note).
- The general Citations page documents char_location, page_location, content_block_location and search_result blocks only; web_search_result_location is documented only on the web search page and the Messages API reference ([platform.claude.com — citations](https://platform.claude.com/docs/en/build-with-claude/citations)).

### 8.3 Gemini API grounding with Google Search (Gemini adapter)

Surfaces and endpoint

- [Proven] The Gemini API Interactions overview (last updated 2026-09-23) states: "As of June 2026, it is Generally Available and recommended for all new projects. While it is now considered legacy, the original generateContent API remains fully supported." The page's REST example posts to https://generativelanguage.googleapis.com/v1beta/interactions. The two surfaces return grounding data in different shapes, so an adapter must target one. Source: [ai.google.dev/gemini-api/docs/interactions](https://ai.google.dev/gemini-api/docs/interactions). The migrate-to-interactions page's REST examples use /v1beta2/interactions while this page and the google-search page use /v1beta; Google's own docs are inconsistent on the path version.
- [Proven] On the Interactions API, the documented Google Search grounding example is a POST to https://generativelanguage.googleapis.com/v1beta/interactions with x-goog-api-key header and body {"model": "gemini-3.8-flash", "input": "Who won the euro 2024?", "tools": [{"type": "google_search"}]}; the example passes no other tool configuration. Source: [ai.google.dev/gemini-api/docs/google-search](https://ai.google.dev/gemini-api/docs/google-search) (last updated 2026-09-23).
- [Proven] Gemini API documentation states "The model analyzes the prompt and determines if a Google Search can improve the answer," runs the search, and returns url_citation annotations in which each annotation "links a text segment (defined by start_index and end_index) to a source URL". Source: [ai.google.dev/gemini-api/docs/google-search](https://ai.google.dev/gemini-api/docs/google-search). The model decides whether to search; log the executed queries from google_search_call.

Where citations live (Interactions API)

- [Proven] On the Interactions API the documented grounded response is a steps[] array. The page says: "google_search_call: Contains the search queries the model executed. google_search_result: Contains search_suggestions, an HTML snippet for rendering search suggestions in your UI. Full usage requirements are detailed in the Terms of Service. text with annotations: The model's synthesized answer with inline citations. Each url_citation annotation links a text segment (defined by start_index and end_index) to a source URL." The example's url_citation objects carry type, url, title, start_index and end_index. The page's response example contains no groundingMetadata object and the page never mentions that term. Source: [ai.google.dev/gemini-api/docs/google-search](https://ai.google.dev/gemini-api/docs/google-search). Caveat: the migrate page's Interactions example uses a different shape (annotations with a 'uri' key and no 'type' field), so the exact wire shape is documented inconsistently.
- [Proven] In the Interactions API reference, UrlCitation.start_index is described as "Start of segment of the response that is attributed to this source. - [Proven] In Perplexity's OpenAPI document the legacy Sonar path is POST /v1/sonar (summary "Create Chat Completion", description "Generate a chat completion response for the given conversation."); async variants live at /v1/async/sonar. Per the API reference, `model` is "Required if neither models nor preset is provided" and `preset` is "Required if model is not provided"; `models` is a fallback chain (max 5) that takes precedence over `model`. `preset` is a plain string whose description gives "fast", "low", "medium", "high", "xhigh" as examples (no enum is declared). `input` is "Input content - either a string or array of input items"; `instructions` is "System instructions for the model"; `max_output_tokens` is optional generally but "required when using anthropic/* models" (the API returns a validation error/HTTP 400 if omitted for an Anthropic model). ## 9. Candidate scoring criteria

Label meanings: evidence-backed = rests on an engine's own documentation or terms, an industry standard's definition, or a peer-reviewed result (with "lab-conditional" where the result holds only once a page is already in context); heuristic = rests on correlational vendor data, preprints, expert opinion or inference.
